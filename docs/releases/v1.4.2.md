Window Layouts for KDE v1.4.2 makes application launch mappings follow the
physical monitor instead of its HDMI or DisplayPort connector.

- Mappings match the monitor's manufacturer, model, and serial number. A
  monitor can move between ports without losing its application placements,
  and a different display on the old port cannot inherit those mappings.
- The mapping editor lists monitor names and serial numbers and flags missing
  or ambiguous destinations. If a monitor has no usable serial, its identity
  and original connector must both match; the editor labels this limitation.
- Existing connector-only mappings need their intended physical monitor
  selected once in Application Launch Mappings. Their layout choices are
  preserved. A connector alone cannot identify which monitor was intended.
- The README now includes the centered top target strip and two nearby-target
  screenshots.

Validation: monitor identity and placement regression tests, real isolated
KWin/Wayland and GTK editor tests, upgrade preservation of physical and legacy
mappings, updater checks, and release metadata checks. Desktop testing confirmed
that applications follow the LG monitor on both HDMI and DisplayPort while
another display uses the old connector.

Install with Check for Updates in Window Layouts. The versioned archive and
SHA-256 checksum attached to this release support the built-in updater.
For a manual upgrade, extract the archive and run `./install-drag-overlay.sh`.
For a new installation, run `./install.sh`.
