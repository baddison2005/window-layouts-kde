Window Layouts for KDE v1.4.1 fixes application launch mappings.

- Opera GX and other apps can match their startup window class even when KWin
  reports a different desktop ID. Exact desktop-ID mappings keep priority.
- Flatpak gedit is recognized by its short window ID when its desktop entry
  supplies no startup class. Conflicting aliases are skipped.
- Newly saved or edited mappings are picked up on the next fresh launch even
  when KDE does not emit its general options-change signal. Windows whose
  identity arrives after activation retain their fresh-launch status.
- The mapping editor flags unavailable monitor connectors and clarifies the
  window readiness modes. Use First eligible window for browsers, Steam, and
  Discord; Steam's non-resizable sign-in window is skipped until the main
  window is ready. Document window remains available for document editors
  with launchers or template choosers.
- Runtime diagnostics explain missing destinations and readiness timeouts.

Existing windows remain in place. Fully quit apps that keep background
processes running before testing another fresh launch. A 30-second grace
period follows script startup or reload to leave session-restored windows alone.

Validation: launch-mapping regression tests (including gedit alias ambiguity
and exact-match priority), process-lifecycle tests, the GTK mapping editor,
real isolated two-display KWin/Wayland launch testing, upgrade preservation,
updater tests, and release metadata checks. Desktop launch tests confirmed
Steam, Opera GX, and gedit; the user's additional application checks passed.

Install with Check for Updates in Window Layouts. The versioned archive and
SHA-256 checksum attached to this release support the built-in updater.
For a manual upgrade, extract the archive and run `./install-drag-overlay.sh`.
For a new installation, run `./install.sh`.
