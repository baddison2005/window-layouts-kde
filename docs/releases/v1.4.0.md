Window Layouts for KDE v1.4.0 adds application launch mappings.

- Choose an application, a fixed or custom layout, and a monitor for its first
  ready window after a fresh launch.
- Use Document window mode for apps with launchers and file/template choosers.
  Required and excluded title fragments support unusual or localized apps.
- Existing windows and later windows from the same running application stay
  in place. Mappings wait for stable geometry and skip unavailable monitors
  and removed custom layouts.
- In-app upgrades refresh the configurator service after installation so the
  new mapping editor becomes available without logging out.
- Open Application Launch Mappings from the panel configuration, or Application
  Mappings from the shared Cairo-Dock/floating-button configurator. Mappings
  have their own Save button. Save custom layouts before assigning them.

Mappings arm 30 seconds after the KWin script starts and wait up to five
minutes for a ready window. Document readiness uses KWin roles and window
titles; title filters offer stricter matching where needed. Fully quit apps
that keep background processes running to trigger another fresh launch.

Validation: process-lifecycle and KWin regression tests, GTK editor Save/Cancel
checks, real two-display headless Wayland launch testing, QML compilation,
existing layout/updater regression tests, and release metadata checks.

Install or upgrade with the in-app updater, or extract the versioned archive
and run `./install-drag-overlay.sh` for an existing installation. For a new
installation run `./install.sh`. Both the archive and its SHA-256 checksum are
attached for the in-app updater.
